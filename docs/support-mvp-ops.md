# Support MVP: минимальный операционный контур

Этот документ описывает базовую работу поддержки для MVP-режима:

- обращения принимаются через `POST /api/v1/support/contact`;
- дальше автоматически пересылаются во внешний helpdesk;
- команда поддержки работает в интерфейсе helpdesk.

## 1. Очередь и каналы

- Единая очередь: `platform_support`.
- Источник тикета: `banyaguide-web`.
- Канал ответа пользователю: email из тикета.

## 2. Минимальный SLA

- Первый ответ: до 4 часов в рабочее время.
- Платежные вопросы: до 2 часов в рабочее время.
- Стандартное решение: до 24 часов.

## 3. Теги и приоритизация

Назначать теги при обработке:

- `topic:payment` — проблемы платежей;
- `topic:booking` — спор или вопрос по брони;
- `topic:account` — вход, профиль, доступ;
- `topic:bug` — техническая ошибка.

Приоритет:

- `high`: платеж не прошел/деньги списаны;
- `normal`: все остальные обращения.

## 4. Обязательный набор данных при ответе

Перед ответом оператор проверяет:

- `request_id`;
- `user_id` и `role`;
- `booking_id` и `payment_id` (если переданы);
- текст обращения и тему.

## 5. Шаблоны быстрых ответов

### Подтверждение получения

```
Здравствуйте! Обращение получено, номер: {{request_id}}.
Мы уже проверяем детали и вернемся с ответом в ближайшее время.
```

### Уточнение данных

```
Здравствуйте! Для проверки обращения {{request_id}} уточните, пожалуйста:
1) дату и время действия;
2) что именно ожидали увидеть;
3) скриншот ошибки (если есть).
```

### Платежный кейс

```
Здравствуйте! Проверяем платеж по обращению {{request_id}}.
Если у вас есть идентификатор платежа (payment_id) или скрин чека, отправьте, пожалуйста, в ответ.
```

## 6. Инцидентный fallback

Если внешний helpdesk недоступен:

1. Проверить логи `api-gateway` по сообщению `support contact forward failed`.
2. Временно перенаправить обращения на резервный канал (почта поддержки).
3. После восстановления повторно отправить пропущенные обращения по `request_id` из логов.
